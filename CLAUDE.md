# NBA Belt

Requirements: docs/spec.md. Architecture and commands: README.md.

## Checks before committing
- `npm test` and `npm run typecheck`.
- UI changes: `npm run dev`, open http://localhost:8787/nba-belt/, check desktop and 375px mobile, light and dark.
  To see the live/next-game states, put a hand-made record in local KV:
  `npx wrangler kv key put --binding BELT --local season:2026 --path <file>` and
  `npx wrangler kv key put --binding BELT --local meta '{"season":2026}'`.

## Things that aren't obvious
- Seasons are named by start year; ESPN's `season.year` is the end year. Hence `espnSeason === season + 1` everywhere.
- ESPN labels the NBA Cup final as a regular-season game (type 2). It's excluded by competition type `CC`
  (`cupFinal` in src/espn.ts). Cup group and knockout games before the final do count.
- The scoreboard's `leagues[0].calendar` lists every game date of the season. For a finished season its last date
  is the Finals clincher, which is how `findChampion` works.
- Fetch from `site.web.api.espn.com`. `site.api.espn.com` returns 403 to most server-side clients (Akamai bot
  filter), and custom User-Agent headers make it worse.
- Free-plan budgets shape the design:
  - 10 ms CPU per Worker run, so fetch only small daily scoreboards, capped per run (`maxFetches`). The per-team
    schedule endpoint is 1.5 MB, too big.
  - 1,000 KV writes a day, so exactly one write per cron run (every 2 min ≈ 720 a day). Don't add per-run writes.
- Static files must live under `public/nba-belt/`: Cloudflare looks assets up by the full request path. Keep the
  single route pattern `electricrelaxation.com/nba-belt*`.
- Everything in src/ except worker.ts must stay runtime-agnostic: tests and the backfill run it in Node.
- Node runs `scripts/*.ts` directly (type stripping), so use erasable TypeScript only and `.ts` import extensions.
- `public/nba-belt/data/*.json` are generated by `npm run backfill`; don't hand-edit them.
